# Как блокировщики сайтов сопротивляются обходу (сводка исследования)

Источники: документация Microsoft Edge и Chrome Enterprise по политикам, Chromium admins docs,
обзоры Cold Turkey / Freedom, материалы о DoH/VPN/прокси (2026).

## Главный вывод
Правка файла **hosts** — самый слабый способ: легко отредактировать и, главное, **обходится DNS-over-HTTPS**
в браузере (браузер сам резолвит имена шифрованно, мимо hosts). К тому же hosts **общесистемный** — нарушил бы
требование «только одна учётка». Поэтому основа этого проекта — **корпоративные политики браузеров**, которые:

- блокируют по URL **внутри браузера** (`URLBlocklist`) — не зависит от DNS/DoH/VPN и работает в инкогнито;
- задаются **per-user** в `HKCU`/`HKU\<SID>` → затрагивают только учётку владельца;
- у Edge надёжно применяются и на домашней (не доменной) Windows; Chrome/Chromium-браузеры (Vivaldi, Brave,
  Яндекс) используют те же имена политик, путь отличается только вендором (`Software\Policies\<Vendor>`).

## Уровни защиты в этом проекте
1. `URLBlocklist` + `IncognitoModeUrlBlocklist` для всех распространённых Chromium-браузеров и `WebsiteFilter`
   для Firefox — блок в любом из этих браузеров, включая инкогнито.
2. `DnsOverHttpsMode=off` (+ `BuiltInDnsClientEnabled=0`), Firefox `DNSOverHTTPS Locked=0` — закрывает обход
   через шифрованный DNS.
3. Непрерывное **самовосстановление** политик службой (убрали из реестра — вернулись за ~1 c).
4. **Закрытие открытых браузеров** при включении блокировки (реестр-политики подхватываются при запуске).
5. **Самозащита службы** (DACL без stop/delete для админов, флаг неостанавливаемости, ACL на папки/ключ,
   восстановление автозапуска и failure-actions) — как в «Стоп-экран».
6. Необязательный **брандмауэр по IP**, привязанный к SID владельца (`-LocalUser`), для программ вне браузера.

## Что остаётся обходимым (отражено в README)
- Браузер без поддержки политик / портативный / Tor Browser.
- Веб-прокси и анонимайзеры не из списка (чёрный список всегда отстаёт; надёжнее белый список).
- Администратор: безопасный режим, загрузка с USB, `URLAllowlist`-исключение.
- Другое устройство/телефон.

## Замечания по надёжности
- Реестровые политики применяются при **старте браузера**; при изменении на лету иногда нужен перезапуск
  браузера (поэтому включение блокировки закрывает браузеры).
- На не-доменной машине Chrome показывает «Управляется организацией» — это ожидаемо для политик.
