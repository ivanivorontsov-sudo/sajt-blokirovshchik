# Проверено / не проверено

## Проверено на сборочной машине (Linux, .NET 8)
- Компиляция всех проектов (Core, Service, App) без ошибок и предупреждений.
- Публикация self-contained single-file `SiteBlocker.exe` (win-x64), валидный PE32+ GUI.
- Юнит-тесты логики ядра — 25 шт., все проходят (`dotnet test`):
  - нормализация доменов (схема/www/порт/путь/мусор, дедуп, разбиение по запятой);
  - PBKDF2-хэш пароля: верная/неверная проверка, отсутствие пароля в JSON, случайная соль, ≥100k итераций;
  - логика разблокировки: блок при наличии сайтов, снятие по времени/до конца сеанса, сброс при перезагрузке,
    выходе из системы и смене сеанса;
  - движок политик: запись `URLBlocklist`/`IncognitoModeUrlBlocklist`/`DnsOverHttpsMode`/Firefox `WebsiteFilter`,
    `IsApplied`/`IsAnyPresent`, снятие, изоляция между кустами разных пользователей (чужая учётка не затронута).
- Синтаксис PowerShell-скриптов (install/uninstall/emergency) — проверен парсером PowerShell 7.

## НЕ проверено (нет Windows-окружения; на ПК Ивана ничего не ставилось)
- Фактическое применение политик браузерами на конкретной машине (особенно Chrome/Vivaldi на не-доменной
  Windows — Edge гарантированно применяет реестровые политики).
- Работа службы Windows, именованного канала, запуск окна в сеансе пользователя, трей.
- Самозащита службы (DACL/ACL), режим обслуживания, аварийное восстановление в безопасном режиме.
- Уровень брандмауэра по IP (экспериментальный).

Рекомендуется первая установка под наблюдением: поставить, задать пароль и 1–2 сайта, проверить блок в Edge и
Vivaldi, проверить разблокировку по паролю и повторный блок после перезагрузки.
